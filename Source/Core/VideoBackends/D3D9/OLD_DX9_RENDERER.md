# Original Dolphin DX9 Renderer (3.x-4.x Era)

Reference documentation for the original DX9 video plugin.
Source: `dolphin-8faefa3672cd4b27f626171981ab5e581f798ba8/Source/Plugins/Plugin_VideoDX9/Src/`

---

## Architecture Overview

The original renderer was a **shader-based** D3D9 backend. It did NOT use fixed-function pipeline -- all GX TEV stages were emulated via dynamically-generated HLSL vertex and pixel shaders. View/World matrices were set to identity; all transforms happened in shader constants.

Key files:
- `VertexManager.cpp` - Geometry buffering, flush pipeline, draw calls
- `Render.cpp` - Frame management, state setup, presentation
- `D3DBase.cpp` - Device creation, state caching wrappers
- `NativeVertexFormat.cpp` - GX-to-D3D9 vertex declaration conversion
- `VertexShaderCache.cpp` / `PixelShaderCache.cpp` - Shader compilation and caching
- `FramebufferManager.cpp` - EFB/XFB render target management
- `TextureCache.cpp` - Texture decoding and GPU caching

## 1. Vertex/Index Buffer Management

### Buffer Setup
- **2 vertex buffers, 2 index buffers** (double-buffered ring buffer)
- `D3DPOOL_DEFAULT`, `D3DUSAGE_DYNAMIC | D3DUSAGE_WRITEONLY`
- VB size: `MAXVBUFFERSIZE` (derived from max primitives x largest vertex)
- IB size: `MAXIBUFFERSIZE * sizeof(u16) * 8`

### Lock Strategy (Critical for RTX Remix)
The buffer management used a **cursor-based ring buffer** with cross-frame persistence:

```
PrepareDrawBuffers(stride):
  1. Align cursor to stride boundary
  2. If cursor + datasize > buffer_size:
       LockMode = D3DLOCK_DISCARD    // Orphan old buffer
       cursor = 0
       Rotate to next buffer: (current + 1) % 2
     Else:
       LockMode = D3DLOCK_NOOVERWRITE  // Append to existing buffer
  3. Lock(cursor, datasize, &ptr, LockMode)
  4. memcpy(ptr, cpu_data, datasize)
  5. Unlock()
  6. SetStreamSource(0, buffer, 0, stride)  // Note: offset=0, uses basevertex instead
  7. SetIndices(buffer)
```

Key insight: DISCARD only happened when a buffer was full (~every 2 frames with typical data sizes). The cursor persisted across frames. This meant very few actual buffer allocations.

### Draw Calls
Three separate DrawIndexedPrimitive calls per flush:
1. **Triangles** (`D3DPT_TRIANGLELIST`) - main geometry
2. **Lines** (`D3DPT_LINELIST`) - wireframe/debug
3. **Points** (`D3DPT_POINTLIST`) - drawn individually via DrawPrimitive

BaseVertex was calculated as `cursor / stride` to index into the ring buffer.

### DrawIndexedPrimitiveUP Fallback
When buffer objects weren't available, `DrawVertexArray()` used user-pointer draws:
```cpp
D3D::dev->DrawIndexedPrimitiveUP(
    D3DPT_TRIANGLELIST, 0, numverts, triangles,
    GetTriangleIndexBuffer(), D3DFMT_INDEX16,
    s_pBaseBufferPointer, stride);
```
This passes vertex/index data directly as CPU pointers with no buffer objects.

## 2. Vertex Format / Declarations

`NativeVertexFormat.cpp` converted GX vertex formats to `IDirect3DVertexDeclaration9`:

```
D3D9 Vertex Elements:
  POSITION     - always float3, offset 0
  NORMAL[0-2]  - up to 3 normals
  COLOR[0-1]   - up to 2 vertex colors (D3DDECLTYPE_D3DCOLOR = BGRA)
  TEXCOORD[0-7]- up to 8 texture coordinate sets
  BLENDINDICES - position matrix index (for matrix palette skinning)
```

Type mapping (GX -> D3D9):
- Size 1: `D3DDECLTYPE_FLOAT1`
- Size 2: `SHORT2N`, `USHORT2N`, or `FLOAT2`
- Size 3: `D3DDECLTYPE_FLOAT3`
- Size 4: `UBYTE4N`, `SHORT4N`, `USHORT4N`, or `FLOAT4`

`SetupVertexPointers()` simply called `D3D::SetVertexDeclaration(d3d_decl)`.

## 3. Shader System

### Approach
All GX TEV stage emulation was done in HLSL shaders. The vertex and pixel shaders were **dynamically generated** based on the current GX state, then compiled and cached.

### Vertex Shaders
- **Game shaders**: Generated by `GenerateVertexShaderCode(components, API_D3D9)` based on active vertex components, lighting, texture generation modes
- **Utility shaders**: Hardcoded HLSL for post-processing, clearing, SSAA

Compilation flow:
```
SetShader(components):
  1. Generate UID from current GX state
  2. Check cache (std::map<UID, VSCacheEntry>)
  3. If miss: GenerateVertexShaderCode() -> D3D::CompileVertexShader()
  4. Cache to disk and memory
  5. dev->SetVertexShader(shader)
```

Transform constants were uploaded via `SetVertexShaderConstantF()`:
- Projection matrix, model-view matrix
- Lighting parameters
- Texture matrices
- Material colors

### Pixel Shaders
- **Game shaders**: Generated by `GeneratePixelShaderCode()` to emulate TEV combiner stages
- **Copy shaders**: For EFB copies with color matrix, gamma, depth conversion
- **Format reinterpretation shaders**: RGBA6-to-RGB8, RGB8-to-RGBA6 conversions

Key utility shaders:
- `ClearProgram`: Simple pass-through (`ocol0 = incol0`)
- `ColorCopyProgram`: Texture sampling with optional color matrix and gamma
- Depth encoding shader: Converts float depth to RGBA components

### Matrices
View and World transforms were set to **identity**:
```cpp
D3DXMatrixIdentity(&mtx);
D3D::dev->SetTransform(D3DTS_VIEW, &mtx);
D3D::dev->SetTransform(D3DTS_WORLD, &mtx);
```
All actual transforms happened in vertex shader constants.

## 4. EFB (Embedded Frame Buffer)

The EFB was emulated with D3D9 render targets:

```
EFB Resources:
  color_texture       - Main color RT (A8R8G8B8, target_width x target_height)
  color_surface       - Surface of color_texture (SetRenderTarget)
  depth_texture       - Main depth RT (D3DFMT_D24X8 or similar)
  depth_surface       - Surface of depth_texture (SetDepthStencilSurface)
  colorRead_texture   - 1x1 RT for single-pixel color readback
  depthRead_texture   - 4x4 RT for depth readback (reduces bandwidth)
  color_OffScreenRead - 1x1 SYSTEMMEM surface for CPU access (GetRenderTargetData)
  depth_OffScreenRead - 4x4 SYSTEMMEM surface for CPU access
  color_reinterpret   - Same-size RT for pixel format conversion passes
```

EFB access flow (PeekColor/PeekDepth):
1. StretchRect from EFB to small read texture
2. GetRenderTargetData to system memory surface
3. LockRect and read pixel value

---

## 5. XFB (External Frame Buffer)

Two modes:
- **Virtual XFB**: Copies EFB to an XFBSource texture via drawShadedTexQuad, presented later
- **Real XFB**: Encodes EFB color data to YUYV format in RAM via TextureConverter

XFBSource::CopyEFB():
1. Set XFB texture as render target
2. Draw fullscreen quad sampling EFB color texture
3. Uses color copy pixel shader with optional gamma
4. Restore EFB render targets

## 6. State Management

`D3DBase.cpp` wrapped all D3D9 state calls with a caching layer to eliminate redundant API calls:

### Cached State Arrays
```
RenderStates[210+46]       - Cached D3D render states
TextureStageStates[9][33]  - Cached texture stage states
SamplerStates[8][15]       - Cached sampler states
Textures[16]               - Cached texture bindings
StreamSources[16]          - Cached stream source bindings
VtxDecl, PixelShader, VertexShader - Cached shader/format state
```

### Two-Tier State System
- `SetRenderState(state, value)` - Permanent change, only calls D3D if value differs
- `ChangeRenderState(state, value)` - Temporary change, tracks dirty flag for later restore
- `RefreshRenderState(state)` - Restores from cache if dirty

This allowed the renderer to temporarily modify state (e.g., for EFB copies) and cheaply restore it.

## 8. Complete Flush Pipeline (vFlush)

This is the core rendering path, called whenever the vertex manager needs to submit a batch:

```
vFlush():
  1. TEXTURE SETUP
     - Scan TEV stages + indirect stages to determine which textures are used
     - For each used texture (up to 8):
       - Set sampler state (filtering, wrap modes)
       - TextureCache::Load() - decode from GC memory, upload to GPU
       - Set pixel shader texture dimension constants

  2. SHADER CONSTANT UPDATE
     - VertexShaderManager::SetConstants() - matrices, lighting, normals
     - PixelShaderManager::SetConstants() - colors, fog, alpha compare

  3. SHADER COMPILATION
     - PixelShaderCache::SetShader(DSTALPHA_NONE, components)
     - VertexShaderCache::SetShader(components)
     - Both use UID-based caching with disk persistence

  4. BUFFER PREPARATION
     - PrepareDrawBuffers(stride):
       - Lock ring buffer (DISCARD or NOOVERWRITE)
       - memcpy vertex + index data
       - Unlock
       - SetStreamSource / SetIndices

  5. VERTEX FORMAT
     - g_nativeVertexFmt->SetupVertexPointers()
       - Sets IDirect3DVertexDeclaration9

  6. DRAW
     - DrawVertexBuffer(stride) or DrawVertexArray(stride)
     - Separate calls for triangles, lines, points

  7. DESTINATION ALPHA PASS (optional)
     - If dstalpha enabled: recompile pixel shader, apply alpha state, draw again

  8. CURSOR ADVANCE
     - m_index_buffer_cursor += total indices used
     - m_vertex_buffer_cursor += numverts * stride
```

## 9. Key Differences from Our Remix Backend

| Aspect | Original DX9 | Our Remix Backend |
|--------|-------------|-------------------|
| Pipeline | Shader-based (HLSL) | Fixed-function (for Remix capture) |
| Transforms | Identity matrices + shader constants | SetTransform(VIEW/WORLD/PROJ) |
| TEV emulation | Dynamic pixel shaders | D3D9 texture stage states |
| Buffer strategy | 2x ring buffer, cursor-based, cross-frame | Currently DrawIndexedPrimitiveUP |
| Draw calls/frame | ~same count but uses VB/IB | Same count, user-pointer draws |
| State caching | Full D3D state cache layer | Direct D3D calls |
| EFB | Full render target emulation | Stubbed (draws to backbuffer) |

## 10. Lessons for RTX Remix Integration

1. **Buffer strategy matters**: The original's ring buffer with infrequent DISCARD minimized driver allocations. For Remix, DrawIndexedPrimitiveUP may be better since it gives Remix exactly the bytes per draw.

2. **Draw call count is inherent to GX emulation**: ~2000-4000 draws/frame is normal. Each GX state change forces a flush. This cannot be easily reduced without breaking emulation accuracy.

3. **Shader system is complex**: The original dynamically generated HLSL for every unique GX state combination. For Remix, fixed-function is preferred, but a simple pass-through vertex shader might be needed if fixed-function causes issues.

4. **State caching was important for performance**: The original filtered all redundant D3D state calls. This could help with Remix overhead too.

5. **The EFB system is the biggest gap**: Our backend currently stubs all EFB operations. The original had full render-target-based EFB emulation. Some games depend on EFB reads for gameplay logic (not just rendering).
